一句话结论：一个每天自动更新的肺癌（EGFR/MET）科研情报看板，试验、文献、靶点、会议数据分层采集，AI 说的每一句话都带编号引用、能回溯到 PMID / NCT / 原文，还能一键导出可编辑的 PPT。

---

## 起因是两个具体的麻烦

第一个是信息量。EGFR 和 MET 这条线上，每周新增的注册试验、文献、会议报道、靶向药进展，一个人靠 RSS 和 PubMed 提醒是跟不完的。真正讲课或者写东西的时候，又要在几十个标签页里翻回原始出处。

第二个更麻烦：用大模型总结这些内容，它会很自然地"补"出一句听起来完全合理、但原文里根本没有的话，随手还配一个看起来很像真的引用。你如果不去逐条核对，就会把它讲出去。

所以我想做的不是"又一个 AI 摘要工具"，而是一个**结论可被机械核查**的情报端。
左侧是时间、主题、试验状态、分期、治疗模式、来源类型、关键词的筛选；中间是统计图表；每张主题卡下面是 AI 解读、靶点药物、在册试验、文献和来源索引。

## 关键设计：让"可溯源"变成约束而不是口号

这套东西里我认为唯一值得说的，是引用是怎么被强制的：

- 所有进入 AI 上下文的材料，先登记进一个统一的来源簿，拿到全局编号 `[n]`；
- 模型输出被要求对每个事实性陈述标注编号；
- 生成后有一道校验：**不存在的编号直接剔除，未使用的来源也剔除，剩下的重新编号**；
- 页面底部就是这份来源索引，点编号能跳到 PubMed、ClinicalTrials.gov 或靶点页面。

换句话说，"AI 编了个引用"这件事在构建阶段就会失败，而不是等到你看出来。日志里会打印每轮的引用数与来源数，我自己的习惯是每次构建后扫一眼这个数——数字对不上就说明这一轮有内容被丢掉了。

数据分层也是明确的：ClinicalTrials.gov、PubTator 3、Open Targets 是证据层；Tavily 只做新闻和会议补充，页面上单独标注，不计入证据强度。

## 会议数据：按年份沉淀，而不是每天重复抓

今年几个大会——ASCO、ESMO、WCLC、AACR、ESMO Asia——我把它们做成了一个"会议库"：每个大会一条配置，构建时自动生成一张卡，里面是从公开报道里逐篇抽出来的**关键试验结果表**（终点、方案、试验、瘤种、HR、95%CI、样本量、是否达到终点），每行都挂着来源编号。

时间筛选是按会议归属月份锚定的，所以筛 9 月只会出 WCLC，不会把 10 月的 ESMO 一起带出来。历史会议过了保鲜期就直接复用归档，不会每天重复消耗检索额度。

需要说明的是：**这张表是模型从报道正文里抽的，可能有误差**。所以表头写着"数字请以原文为准"，每一行都能点回原文核对。重要结论我仍然会自己看一遍原文。

## 导出 PPT：为了讲课那个场景

讲课不能拿着网页投屏，所以做了导出：生成的是真正的 `.pptx`，图表和表格是 PowerPoint 原生对象，能右键改数据、能换配色、能改字号。


导出内容跟着当前筛选走——你在看板上筛出什么，PPT 里就只有什么；会议内容默认不导出，需要时勾一下。


这一步其实最花时间。中间踩过的坑不体面但值得记一笔：中文字体用 PingFang 之类的，在这套渲染链路上会丢字（"突变"渲染成"突"），最后只能用 Arial Unicode MS；东亚字体元素在 OOXML 里必须紧跟拉丁字体元素，顺序错了同样丢字。这类问题不逐页渲染出来看，是发现不了的。

## 部署：把一段提示词复制给 agent 就行

我不想让"开源"变成"你先装个环境再说"。所以写了一份部署文档，最上面是一段可以直接复制的提示词——粘到 DSH、Claude Code、Cursor 这类能执行命令的 agent 平台，它会自己克隆、装依赖、问你要密钥、构建数据、起服务、验证，最后把访问地址和停服命令报给你。

```text
请把 GitHub 仓库 https://github.com/ChrisLou-bioinfo/AImednews 部署到当前机器并启动看板。
1) 克隆到 ./AImednews 并进入；2) 建 .venv 装 requirements.txt；
3) 复制 .env.example 为 .env，向我索取 TAVILY_API_KEY 与 DEEPSEEK_*（没有密钥就用冒烟参数先跑起来）；
4) 有密钥执行 python news/build_dashboard.py --days 7 --synth，
   无密钥执行 python news/build_dashboard.py --days 7 --no-news --no-lit --no-targets；
5) 后台启动 python webapp/server.py --port 8899，验证 /api/health 返回 {"ok":true}；
6) 若支持 systemd/cron/launchd，配置每日 08:00 自动重建（news/run_daily.sh）；
7) 汇报访问地址、产物路径、日志位置、缺失配置与停服命令。
约束：不要改业务代码，不要用 Docker，报错先查 docs/DEPLOY.md。
```

也可以手动来，一条 `bash scripts/setup.sh`：建虚拟环境、装依赖、生成配置模板、按你有没有密钥决定做完整构建还是冒烟构建。

整个东西是纯本地 Python（标准库 HTTP 服务 + 定时脚本），没有数据库、没有 Node、没有 SaaS。没有密钥也能先跑起来看界面，只是新闻和文献层会是空的。

## 几个诚实的边界

- AI 抽取有误差，尤其是会议报道里的 HR 和置信区间，不同报道口径还可能不一致（中期分析和最终分析）；
- 会议覆盖不均：注册试验结果密集的大会（ASCO/ESMO/WCLC）覆盖较好，以早期机制研究为主的大会能抽到的"疗效+HR"条目本身就少；
- Tavily 免费额度有限，全量每日更新会消耗额度，所以做了历史会议缓存和多档降级；
- 界面、解读、PPT 都是中文，数据源本身是英文。
